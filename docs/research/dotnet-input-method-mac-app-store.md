# Can Pāli Key be a .NET Input Method on the Mac App Store?

Research for [issue #33](https://github.com/jamestran1/bogopali/issues/33), part of the macOS wayfinder map ([#31](https://github.com/jamestran1/bogopali/issues/31)). Researched on 2026-11-28 against the macOS 27.2 SDK, the .NET 11.0.100 SDK and the `dotnet/macios` main branch.

## Verdict

**Not feasible** as asked. The blocker is the Mac App Store, not .NET.

- An Input Method cannot be shipped through the Mac App Store today. Apple's Developer Technical Support said so in 2020 and repeated it in April 2026, and the only registration API accepts input method bundles only from the shared `Input Methods` folders that a store app may not install into.
- Building the Input Method in C# is **technically feasible with caveats**: `net11.0-macos` does not bind InputMethodKit yet, but a binding PR is open in `dotnet/macios`, and a hand-written binding of the few classes needed is small. That only matters for distribution outside the store (Developer ID, notarized), which issue #33 rules out.

Each finding below is marked **Verified** (read in a primary source, linked) or **Inference** (my reasoning from verified facts, not confirmed by a source).

## 1. Does `net11.0-macos` bind InputMethodKit?

- **Verified: not bound in the shipping SDK.** `dotnet/macios` lists `InputMethodKit` among "macOS only - unsupported frameworks" in its API-coverage filter ([Filter.cs](https://github.com/dotnet/macios/blob/main/tests/xtro-sharpie/xtro-sharpie/Filter.cs)) and in the ignored frameworks of the coverage Makefile ([Makefile](https://github.com/dotnet/macios/blob/main/tests/xtro-sharpie/Makefile)). Only a library path constant exists, `Constants.InputMethodKitLibrary` ([Constants.cs](https://github.com/dotnet/macios/blob/main/src/ObjCRuntime/Constants.cs)).
- **Verified: the request is old and still open.** [dotnet/macios#7487](https://github.com/dotnet/macios/issues/7487) "Bindings for the framework are missing" is open. A maintainer said in [#16070](https://github.com/dotnet/macios/issues/16070) that binding a system framework yourself with a binding project "isn't a supported use case".
- **Verified: a fix is in review, not merged.** [dotnet/macios#27172](https://github.com/dotnet/macios/pull/27172) (opened 2026-10-29, Copilot-authored, open) binds `IMKServer`, `IMKInputController`, `IMKCandidates` and the input, state-setting, mouse-handling and text-client protocols. Its description says runtime validation was limited by the missing Xcode 27.1 toolchain, and its CI run reported 8 failed tests. It would ship in a future workload release at the earliest.
- **Inference: a manual binding is small.** The classic Xamarin.Mac model lets C# register Objective-C subclasses (`[Register]`, `[Export]`) of any class that has a managed wrapper. Pāli Key needs only: `IMKServer` `initWithName:bundleIdentifier:`, an `IMKInputController` subclass overriding `inputText:client:` (or `handleEvent:client:`), `commitComposition:` and `menu`, plus calls on the client proxy (`insertText:replacementRange:`, `setMarkedText:selectionRange:replacementRange:`) which can go through `ObjCRuntime.Messaging`. That is perhaps 100 to 200 lines, but it is unsupported, and the registrar may need care with a framework the SDK does not know. Not tried here: the `macos` workload is not installed on this machine (`dotnet workload list` shows `ios`, `maccatalyst`, `maui`, `android` only) and installing it was out of scope.

## 2. What an Input Method bundle requires

- **Verified: install location.** The `TISRegisterInputSource` documentation in the macOS 27.2 SDK header (`HIToolbox.framework/Headers/TextInputSources.h`) says it "can only be used to register ... Input method bundles in the new "/Library/Input Methods/" or "~/Library/Input Methods/" directories". The same header documents the `TISInputSourceID` and `TISIntendedLanguage` plist keys.
- **Verified: process model.** Apple's [NumberInput_IMKit_Sample `main.m`](https://developer.apple.com/library/archive/samplecode/NumberInput_IMKit_Sample/Listings/trunk_NumberInput_0_main_m.html) creates one `IMKServer` with a connection name ("periods and spaces are not allowed in the connection name") and the bundle identifier, then runs `NSApplication` "because in this case the input method is a background only application". The [`IMKInputController`](https://developer.apple.com/documentation/inputmethodkit/imkinputcontroller) docs say the server creates one controller per client input session.
- **Verified (community, not Apple):** the remaining `Info.plist` keys (`InputMethodConnectionName`, `InputMethodServerControllerClass`, `tsInputModeListKey`, `LSBackgroundOnly`) are not documented on a current Apple page; they come from the archived sample project and from input method authors. An experienced IME author asks Apple to document that `InputMethodConnectionName` should be `$(PRODUCT_BUNDLE_IDENTIFIER)_Connection`, because a mismatched name is refused by the sandbox ([ShikiSuen, "Let's talk about what InputMethodKit needs to improve"](https://gist.github.com/ShikiSuen/73b7a55526c9fadd2da2a16d94ec5b49)).
- **Inference: a .NET for macOS app bundle can satisfy this.** The keys are plain `Info.plist` entries, `LSBackgroundOnly` is supported, and `main` can create the server before running the app loop. Nothing found in `dotnet/macios` prevents it. The user enables it in System Settings > Keyboard > Text Input > Input Sources > Edit, then picks it from the input menu ([Apple support](https://support.apple.com/guide/mac-help/mchl84525d76/mac)).

## 3. Are third-party Input Methods accepted on the Mac App Store?

- **Verified: no.** In [Developer Forums thread 134115](https://developer.apple.com/forums/thread/134115), asked "Is there a sanctioned way to distribute IMEs via the Mac App Store?", Apple DTS (Quinn "The Eskimo!") answered in June 2020: "No. The iOS mechanism, keyboard extensions, is not supported on macOS ... your only option is to distribute outside of the Mac App Store." Asked again in April 2026, DTS replied that the way forward would be for Apple to add something like an iOS keyboard extension to macOS and asked for enhancement requests. So nothing changed as of April 2026.
- **Verified: the guidelines that block it.** [App Review Guideline 2.4.5](https://developer.apple.com/app-store/review/guidelines/#2.4.5): (i) Mac App Store apps "must be appropriately sandboxed"; (ii) they "must also be self-contained, single app installation bundles and cannot install code or resources in shared locations"; (iv) they "may not download or install standalone apps ... or additional code". Combined with the `TISRegisterInputSource` location rule above, a store app cannot place an input method where macOS will load it. The guidelines contain no input method or macOS keyboard extension rules (keyboard extension rules in 4.4.1 are iOS only).
- **Verified: earlier rejection precedent.** [Forum thread 43817](https://developer.apple.com/forums/thread/43817) (2016): a Chinese input method based on the Apple sample was rejected from the Mac App Store as a background-only app with no user interface. A later poster reports that "the official answer from Apple was no".
- **Verified: Apple's own macOS 27 docs do not add a store path.** The [InputMethodKit](https://developer.apple.com/documentation/inputmethodkit) documentation still describes only `IMKServer`, `IMKInputController` and `IMKCandidates`; no app extension point for input methods was found.
- **Not found:** no Mac App Store listing of a third-party input method that installs a selectable input source. Store apps that mention input sources (for example input source switchers) only switch between existing sources. Input methods that are sandboxed (such as vChewing, per the gist above) are distributed outside the store.

## 4. Can a .NET for macOS app go on the Mac App Store at all?

This is no longer the deciding question, but for the record:

- **Verified:** `dotnet/macios` documents Mac App Store submission for Mac Catalyst and says it is "similar" for other platforms: `CreatePackage`, `EnablePackageSigning`, `PackageSigningKey` ("3rd Party Mac Developer Installer"), and `com.apple.security.app-sandbox` in `Entitlements.plist` ([preparing-your-app-for-testflight.md](https://github.com/dotnet/macios/blob/main/docs/preparing-your-app-for-testflight.md)). `CreatePackage` and `EnablePackageSigning` apply to macOS projects ([build-properties.md](https://github.com/dotnet/macios/blob/main/docs/building-apps/build-properties.md)).
- **Verified: universal build.** Release builds of `net*-macos` default to `RuntimeIdentifiers` `osx-x64;osx-arm64` when the minimum OS is below 27.0, and to the host architecture only from 27.0 ([configuration-properties.md](https://github.com/dotnet/macios/blob/main/docs/configuration-properties.md)). A macOS 13+ target therefore builds universal by default.
- **Inference:** no .NET 11 specific blocker was found. Size is larger than a Swift app (self-contained runtime), which ADR 0004 already accepts for the Microsoft Store.

## 5. Composition model and fit with Telex and the Diacritic Cycle

- **Verified:** [`IMKServerInput`](https://developer.apple.com/documentation/inputmethodkit/imkserverinput) offers three ways to receive keys: key binding (`inputText:client:` plus `didCommandBySelector:client:`), unpacked text data (`inputText:key:modifiers:client:`), or raw `NSEvent`s (`handleEvent:client:`). Returning `NO` passes the key on to the app.
- **Verified:** Apple's sample keeps typed characters as **marked text** with `setMarkedText:selectionRange:replacementRange:`, then commits with `insertText:replacementRange:`; `commitComposition:` is called when the session ends and must flush the buffer ([NumberInputController.m](https://developer.apple.com/library/archive/samplecode/NumberInput_IMKit_Sample/Listings/trunk_NumberInput_2_NumberInputController_m.html)).
- **Inference: Telex fits well.** The Input Buffer maps to marked text: `a` shows marked `a`, `f` replaces it with marked `ā`, another `f` steps the Diacritic Cycle, and any key that cannot extend a Telex Rule commits. No Replacement (erase-and-retype) is needed, so the backspace-and-send approach of ADR 0002 disappears on macOS. The cost is the underline on the pending letter, which a direct `insertText:replacementRange:` with a real replacement range could avoid in apps that support it.
- **Verified: settings menu.** [`IMKInputController.menu()`](https://developer.apple.com/documentation/inputmethodkit/imkinputcontroller/menu()) "Returns a menu of commands that are specific to an input method" and is called "whenever the menu needs to be drawn"; [`IMKStateSetting.showPreferences(_:)`](https://developer.apple.com/documentation/inputmethodkit/imkstatesetting) opens a preferences window. So Pāli Key settings can hang off the input source menu.

## 6. Swift or Objective-C fallback via NativeAOT

- **Verified:** NativeAOT can publish a .NET class library as a self-contained native shared library whose `[UnmanagedCallersOnly(EntryPoint = ...)]` methods are callable from other languages; only shared libraries are supported and unloading is not ([Building native libraries](https://learn.microsoft.com/en-us/dotnet/core/deploying/native-aot/libraries)). `Bogopali.Core` is platform-neutral, so it is a good candidate.
- **Inference:** a Swift Input Method shell (a few hundred lines) calling a NativeAOT `libBogopaliCore.dylib` through a small C ABI (for example "feed key, get marked text or commit text") is straightforward and avoids the missing binding. It does **not** change the store verdict: a Swift input method is equally barred from the Mac App Store.

## Consequences for issue #34

- Under the "Mac App Store is mandatory" constraint, the Input Method option is out. The event tap option (sister research ticket) is the remaining path to the store.
- If the store constraint is ever relaxed, an Input Method distributed with Developer ID and notarization is viable, in C# (manual binding now, or the official binding once #27172 ships) or as a Swift shell over a NativeAOT `Bogopali.Core`.
- Worth watching: [dotnet/macios#27172](https://github.com/dotnet/macios/pull/27172) and any WWDC announcement of a macOS input method extension point.
